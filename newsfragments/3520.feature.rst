Added asynchronous, cross-process file locks. `trio.open_file` and `trio.Path.open` now accept ``lock=True`` (or a configured `trio.FileLock`), so the lock is acquired before the file is handed out and released when the file object is closed -- including on task cancellation, exceptions, and process termination (the OS releases the kernel lock even after a crash). `trio.FileLock` supports blocking and bounded (``timeout``) waits -- timeouts raise the distinct `trio.FileLockTimeout`, never an `OSError` -- reads the current holder's pid and acquisition time, and takes over stale locks according to `trio.StaleLockPolicy` with diagnostic evidence in `FileLock.last_takeover`. Added `trio.open_file_lock`, `trio.open_temp_file`, and `trio.open_state_file` convenience entries, and `trio.run_process` now flushes, closes, and unlocks asynchronous (locked) file objects passed as ``stdin``/``stdout``/``stderr`` once the child exits. Platforms or filesystems without locking support raise `trio.FileLockUnsupported` instead of silently continuing.
